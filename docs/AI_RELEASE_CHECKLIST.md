# AI release checks

Automated checks run for pull requests and main pushes on macOS, Linux and Windows. Release builds depend on these checks: TypeScript, Vitest, the production frontend/startup-bundle check, and native Rust tests.

The regression suite uses mocked providers, temporary filesystem fixtures, DOM components and an IndexedDB test implementation. It does not contact a paid model, SSH host or third-party integration. Before publishing, also run these smoke checks in the packaged application using a disposable workspace and test SSH host, never production data.

1. Start and type in a fresh terminal, change directory, and select **Use current terminal workspace**. Check that the chat uses that directory. Switch tabs and restore a closed terminal from its chat.
2. Try an API model and each installed signed-in CLI. Stop while starting and while streaming, then immediately send a new request. Late output must not change the new reply or run another action.
3. Ask to create a small script with workspace edits disabled: nothing may be written. Enable edits and ask again: review the complete diff, apply it, then Undo. Enable auto-apply and check that only eligible local proposals apply; full overwrites and protected files must still need review.
4. Propose an edit, then change the file yourself, switch the chat's workspace, or revoke edit access. Applying the stale proposal must fail without replacing your changes.
5. In Task Mode, run a passing and a failing verification command. A later unrelated passing command must not hide the failure. Apply another edit: the previous checks must become stale. Pause terminal steps before a delayed planner response arrives; no next command may run.
6. Approve a terminal command only after checking its target. If the focused terminal, directory or SSH host changes while approval is open, Husk must refuse and ask for a fresh review. Test destructive commands only as proposals; discard them.
7. On the test SSH host, edit a small UTF-8 file and Undo. Attempt to read/edit a file larger than 256 KiB and a binary file: they must fail rather than become partial editable text. On connection timeout, verify the remote file before retrying; an already-completed remote action cannot be rolled back by cancellation.
8. Switch between two chats with different attachments, proposed edits and integration approvals. No attachment or review from the other chat should appear. Check that an integration returning an error stays failed and retryable, not completed.
9. Open Settings in its separate window. Change provider and a test API key, then return to the chat. Confirm selection/key refresh and that named providers do not inherit a previous provider's endpoint. Check a custom Local model survives restart.
10. Attach a screenshot to a vision-capable API model and ask about its contents. CLI chat must clearly refuse image attachments. In a throwaway text attachment, include a fake secret and exceed the context budget: review both warnings and ensure the chosen omissions/consent are preserved.
11. Open an older installation's chat archive, stream a response, immediately close normally and reopen. Verify chats, drafts and titles survive, incomplete tasks restore paused, and a storage failure produces a visible retry warning. Abrupt OS/process termination can still lose the last uncommitted batch.

## On-screen AI smoke checks

Use both a narrow docked layout and the full window, with light/dark themes and keyboard navigation. These features use the current provider; test an API provider and an installed signed-in CLI. No workspace or SFTP connection should be opened just to explain selected text.

For Codex with ChatGPT sign-in, also test an installation saved with `gpt-5.4-mini` or `gpt-5.4`: the settings and actual CLI launch must use the documented `gpt-5.6-luna` / `gpt-5.6-terra` replacements. A stale local model cache must not re-offer retired selections; a selected model absent from the cache must remain visibly labelled as a saved selection. Refreshing the picker should reread the local cache, and **Codex default** must remain available. Simulated unsupported-model errors should show readable guidance, not raw JSON or credentials. API and custom/local model identifiers must not receive this subscription-only migration. See [OpenAI's Codex retirement guidance](https://learn.chatgpt.com/docs/models#deprecated-codex-models).

1. Select two terminal lines and choose **Explain here**; repeat with editor text. Check that the popover stays on screen, line links reveal the exact selection, Escape closes it and typing still works afterward. **Ask more** must only prepare a draft. **Save to Vault** must save the explanation with its excerpt. Try an oversized selection and a fake `password=example-secret`: no provider request should be sent.
2. Run `printf 'first\n'` twice in a disposable local terminal: **Compare with previous** should show the same output without any AI call. Repeat a command whose output changes and check added/removed lines and exit codes. Only **Explain changes** contacts AI; every observation must link to captured evidence. Change directory, terminal, or SSH connection: runs from different targets must not be paired. Exceed scrollback/capture limits: the comparison must say it is partial. SSH shells without reliable command markers/host/CWD must not produce a guessed comparison.
3. Select `ls -l`, choose **Modify command with AI…**, and ask for human-readable sizes. Review the before/after proposal. **Stage in terminal** must insert a single line without executing it. Existing prompt text must remain untouched; a busy terminal, alternate screen, changed directory, changed host or closed/replaced terminal must refuse staging. Request an unsupported dry-run mode: the model should explain the limitation, not invent a flag; always manually review any proposal.
4. Open **Beautiful Logs**, filter to errors, and choose **Highlights**. Nothing should be sent before **Analyze**. Let new output arrive: the reviewed sample and evidence links must remain unchanged. Repeat with a selected subset of lines and with blank lines in the stream. Close, stop, disable AI or switch terminal while analyzing: no late finding should appear. Missing or fabricated evidence IDs must show a retryable error.
5. Open **Ctrl+R** in a local shell, or right-click **History…**: normal fuzzy search must remain local and responsive without clearing input or interrupting a running process. SSH's native Ctrl+R should still reach the remote shell. Switch to **Ask AI** and describe a saved command. Inspect the candidate sample and exclude an entry before **Find matches**. Results must contain only checked, actual history entries; unknown dates/hosts must not be fabricated. No strong match should be explicit. Changing the query or terminal while searching must invalidate the old response. Selecting a match must stage it without Enter and refuse to overwrite an existing draft, including when the cursor is at Home. Reconnecting to the same SSH host must invalidate the old staging target.

6. Select one terminal command: the compact action bar must not steal focus or submit anything. **F6** focuses it, Escape returns to the terminal, and normal Enter/copy/paste retain shell behavior. Multiline selections offer Explain/Save but not command review; selections beyond the AI budget still allow bounded local saving. Scroll, deselect, change tabs, open a context menu or close the pane: stale controls must disappear.
7. Right-click a draft such as `sudo rm -rf $TARGET` and choose **Review before running…** without executing it. Confirm local hints, captured/unknown shell scope and explicit unknowns. No request happens until **Explain effects with AI**. Review must have no Run/Stage button, must not invent resource counts or inspections, and must block likely credentials. Stop/close/disable AI during a request: no late interpretation should appear.
8. In a disposable local folder where `fixed.txt` does not exist, run `test -f fixed.txt || { printf 'error: fixed.txt missing\n'; false; }` (exit 1), `touch fixed.txt`, then repeat the exact verification command (exit 0). **Remember this fix** should appear only for a captured failure with error evidence followed by the exact successful verification command. Review title/notes, exclude an unrelated successful step, leave the optional error excerpt unchecked and explicitly confirm/save. No output or commands should be persisted before save. Saving must show a brief confirmation and remove the strip, not automatically open the library. Right-click the terminal → **Saved fixes…**, close with **×**, reopen through the menu, and close with **Escape**: records must remain intact, with focus returned to that terminal and no permanent library row. Repeat with AI disabled, no selection, no saved records and after deleting the last fix. Switching terminal/app views must close the library without removing saved fixes. Check **Storage & retention** in the current-fix review and saved library. Reproduce the same failure: **Previous fix found** is copy-only. Verify deletion, reload persistence and full/unavailable storage errors. Changing cwd/host/connection, unknown exits and partial captures must clear the pending chain; missing remote shell integration must not fabricate one.
9. Generate pending file edits, an integration action and a composer terminal approval. **Review · N** must count only the current chat's unresolved items; switching chats and resolving/discarding items updates it immediately. Use keyboard navigation to open each exact approval card, including a collapsed queue. Focus must land on the card, not an Apply/Run control. The indicator itself must never invoke an action.
10. In **Beautiful Logs**, capture `name,time` / `build,2ms` / `test,4ms` as separate CSV rows and choose **Explore**. Check sorting, filtering, exact displayed values, compatible numeric charts and links to frozen source. Repeat with TSV, flat JSON, nested JSON, very large numbers, mixed units, negative values, truncated input and plain text. Unsupported data stays text-only or has no chart. New live output must not alter the frozen sample. Explore remains local with AI disabled.

Automated tests and these checks reduce release risk; they are not a guarantee that every provider version, remote shell or operating-system configuration is supported.
